异步编程 ​

学习目标

  • 理解 async fn、Future 与执行器（executor）的关系
  • 使用 #[tokio::main] 启动异步运行时，并用 .await 驱动任务
  • 用 tokio::join!、tokio::spawn、tokio::select! 组织并发
  • 区分异步等待与阻塞（blocking）调用，避免阻塞工作线程

为什么需要异步 ​

并发并不只有“开线程”一种方式。每个操作系统线程都有独立的栈和调度开销，成千上万个连接若各占一个线程，内存与上下文切换成本会迅速上升。异步（async）模型把等待 I/O 的任务表示成状态机，由少量线程驱动大量任务：任务在等待时不占用线程，数据就绪后再继续执行。

这种模型适合 I/O 密集型（I/O-bound）场景：网络服务、数据库客户端、文件与定时任务。CPU 密集型（CPU-bound）计算仍应交给线程池，否则会阻塞执行器。

async/await 与 Future ​

async fn 调用后不会立即执行函数体，而是返回一个实现了 Future 的值。Future 表示“未来某刻会产出结果的计算”，只有被轮询（poll）时才向前推进。.await 负责挂起当前任务，把控制权交还执行器，等 Future 就绪后再恢复。

rust
async fn fetch_user(id: u64) -> String {
    // 返回类型是 impl Future<Output = String>
    format!("user-{id}")
}

编译器会把 async fn 转换成状态机，每个 .await 是一个可能暂停的恢复点。手写 Future 需要处理 Pin、Context 与 Waker，日常开发几乎不需要直接实现它。

tokio 运行时 ​

异步函数需要执行器来轮询。tokio 是 Rust 生态中最常用的异步运行时（runtime）。#[tokio::main] 宏把 main 包装成启动运行时的同步入口，并在其中阻塞等待异步主体完成。

tokio::join! 同时等待多个 Future，全部完成后返回元组。它不会创建新线程，而是在同一个任务内并发推进：

用 join! 并发等待多个请求Rust 2021
use std::time::Duration;

async fn fetch(name: &str, ms: u64) -> String {
    tokio::time::sleep(Duration::from_millis(ms)).await;
    format!("{name} 完成")
}

#[tokio::main]
async fn main() {
    let start = std::time::Instant::now();

    let (a, b, c) = tokio::join!(
        fetch("请求 A", 50),
        fetch("请求 B", 80),
        fetch("请求 C", 30)
    );

    println!("{a} / {b} / {c}");
    println!("总耗时约 {} ms", start.elapsed().as_millis());
}

tokio::spawn 与独立任务 ​

tokio::spawn 把 Future 提交为独立任务，由运行时调度，可能在不同线程上执行。它要求 Future 满足 Send + 'static，因此不能借用栈上的局部变量。JoinHandle 的 .await 返回 Result，任务 panic 会被包装成错误。

用 spawn 创建并发任务Rust 2021
use std::time::Duration;

async fn work(id: u32) -> u32 {
    tokio::time::sleep(Duration::from_millis(40)).await;
    id * 10
}

#[tokio::main]
async fn main() {
    let start = std::time::Instant::now();

    let first = tokio::spawn(work(1));
    let second = tokio::spawn(work(2));

    let a = first.await.unwrap();
    let b = second.await.unwrap();

    println!("结果: {a}, {b}");
    println!("耗时: {} ms", start.elapsed().as_millis());
}

任务一旦创建就会开始调度，不需要像线程那样显式 join；但若提前丢弃 JoinHandle，运行时仍会执行任务，只是调用方拿不到结果。

select! 与取消 ​

tokio::select! 同时等待多个分支，第一个完成的胜出，其余分支的 Future 被丢弃。这天然实现了超时与竞速：

用 select! 等待最先完成的任务Rust 2021
use std::time::Duration;

async fn fast() -> &'static str {
    tokio::time::sleep(Duration::from_millis(20)).await;
    "快速任务"
}

async fn slow() -> &'static str {
    tokio::time::sleep(Duration::from_millis(60)).await;
    "慢速任务"
}

#[tokio::main]
async fn main() {
    tokio::select! {
        value = fast() => println!("先完成: {value}"),
        value = slow() => println!("先完成: {value}"),
    }
}

被丢弃的分支相当于取消（cancellation）。因此 select! 中的 Future 必须能安全地在任意 .await 点被丢弃，不能依赖“一定会执行到结尾”的清理逻辑，应使用 Drop 或专门的守卫类型。

阻塞边界 ​

异步运行时只有少量工作线程。在 async 函数中调用 std::thread::sleep、同步文件 I/O 或长时间计算，会占住整个工作线程，导致同一线程上的其他任务无法推进：

rust
use std::time::Duration;

async fn bad_sleep() {
    // 错误示范：阻塞当前工作线程，而不是让出执行权
    std::thread::sleep(Duration::from_millis(100));
}

#[tokio::main]
async fn main() {
    bad_sleep().await;
}

常见错误 ​

tokio::spawn 的 Future 必须是 'static。捕获局部变量的引用会编译失败：

rust
#[tokio::main]
async fn main() {
    let data = String::from("hello");
    let handle = tokio::spawn(async {
        println!("{data}");
    });
    handle.await.unwrap();
}

练习 ​

练习

并发模拟 3 个请求，耗时分别为 30 ms、50 ms、20 ms。使用 tokio::join! 汇总每个请求的耗时，并打印“单个耗时之和”与“实际并发耗时”。

参考答案
并发请求耗时统计Rust 2021
use std::time::{Duration, Instant};

async fn request(id: u32, ms: u64) -> (u32, u64) {
    tokio::time::sleep(Duration::from_millis(ms)).await;
    (id, ms)
}

#[tokio::main]
async fn main() {
    let start = Instant::now();

    let (a, b, c) = tokio::join!(
        request(1, 30),
        request(2, 50),
        request(3, 20)
    );

    let total = a.1 + b.1 + c.1;
    println!("请求 {}、{}、{}", a.0, b.0, c.0);
    println!("单个耗时之和: {total} ms");
    println!("实际并发耗时: {} ms", start.elapsed().as_millis());
}

小结 ​

  • async fn 返回惰性的 Future，.await 才会驱动其执行。
  • #[tokio::main] 启动运行时；join! 在同一任务内并发等待，spawn 创建独立任务。
  • select! 返回最先就绪的分支，其余分支被取消。
  • 异步代码中禁止直接阻塞，改用 tokio::time::sleep 或 spawn_blocking。
  • spawn 要求 Send + 'static，需要跨任务共享的数据应使用拥有所有权的类型。
