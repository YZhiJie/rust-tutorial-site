测试与文档 ​

学习目标

  • 用 #[test] 与断言宏编写单元测试（unit test）
  • 区分单元测试、集成测试（integration test）与文档测试（doc test）
  • 让测试返回 Result，并用 cargo test 筛选与并行执行
  • 用 rustdoc、rustfmt、clippy 把文档与风格检查纳入日常流程

问题背景 ​

借用检查器能排除内存错误与数据竞争，却无法判断业务规则是否正确：税率算错、边界条件漏判、错误信息写反，编译器都不会报错。依靠手工运行和 println! 验证的问题在于不可重复——改动一行代码后，没人能保证之前验证过的路径仍然正确。

测试（test）的本质是把期望写成可执行代码，让机器在每次修改后重新验证。Rust 把测试工具直接放进 Cargo：不需要额外框架，cargo test 就能编译并运行单元测试、集成测试和文档中的示例。

测试函数的形状 ​

一个测试就是一个带 #[test] 属性的普通函数：

rust
#[test]
fn addition_works() {
    assert_eq!(2 + 2, 4);
}

规则很简单：

  • 函数不接受参数，返回类型为 () 或 Result；
  • 正常返回表示通过，发生 panic 表示失败；
  • 测试默认多线程并行执行，先后顺序不保证，因此测试之间不能依赖共享状态；
  • 测试函数名不参与逻辑，但应描述“被验证的行为”，而不是 test1、test2。

#[test] 只在 cargo test 构建的测试目标中生效；普通 cargo build 不会生成测试运行器。

断言宏：把期望写清楚 ​

标准库提供三个常用断言宏，失败时都会 panic 并打印左右两边的值：

rust
#[test]
fn assertions() {
    let values = vec![1, 2, 3];
    assert!(!values.is_empty());
    assert_eq!(values.len(), 3);
    assert_ne!(values.len(), 4);
    assert_eq!(values.first(), Some(&1), "首个元素应为 1");
}

返回 Result 的测试 ​

测试也可以返回 Result，用 ? 传播错误。Err 会让测试失败，并以 Debug 格式输出错误：

rust
#[test]
fn parses_header() -> Result<(), String> {
    let value: u32 = "42"
        .parse()
        .map_err(|e| format!("解析失败: {e}"))?;
    if value != 42 {
        return Err(format!("期望 42，实际为 {value}"));
    }
    Ok(())
}

模块内单元测试 ​

单元测试通常与被测代码放在同一文件，通过 #[cfg(test)] 只在测试构建时编译：

rust
pub fn slugify(input: &str) -> String {
    assert!(!input.trim().is_empty(), "输入不能为空");
    input.trim().to_lowercase().replace(' ', "-")
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn trims_and_lowercases() {
        assert_eq!(slugify("  Hello Rust "), "hello-rust");
    }

    #[test]
    #[should_panic(expected = "输入不能为空")]
    fn rejects_blank_input() {
        slugify("   ");
    }
}

use super::* 让测试模块访问父模块的私有项，这是单元测试能验证内部实现的关键。#[cfg(test)] 保证测试模块不会进入发布构建。#[should_panic(expected = "...")] 用来验证 panic，但预期字符串应稳定，避免依赖完整错误文本；正式代码中更推荐返回 Result 而不是 panic。

集成测试：从外部调用公开 API ​

集成测试放在项目根目录的 tests/ 下，例如 tests/api.rs：

rust
use my_crate::slugify;

#[test]
fn slugify_is_public_api() {
    assert_eq!(slugify("Hello World"), "hello-world");

文档测试：让示例不腐烂 ​

写在文档注释中的代码块会被 rustdoc 抽取为文档测试（doc test）：

rust
/// 把空白替换为连字符。
///
/// # 示例
///
/// ```
/// assert_eq!(my_crate::slugify("a b"), "a-b");
/// ```
pub fn slugify(input: &str) -> String {
    input.trim().replace(' ', "-")
}

cargo test 会同时运行这些示例，示例无法编译或断言失败都会让测试失败。常用控制属性写在代码围栏上：

  • ignore：跳过该示例；
  • no_run：只编译不运行，适合网络或文件操作；
  • should_panic：示例应当 panic；
  • 以 # 开头的行会被隐藏，常用于 use 与准备代码。

cargo doc --open 生成并打开 HTML 文档。若希望公开 API 必须有文档，可在 crate 根加 #![warn(missing_docs)]，再由 CI 把警告视为错误。

可运行示例：在 main 中执行断言 ​

在线 Playground 没有 cargo test 运行器，下面的示例把同样的断言放进 main，用于观察断言通过或失败时的行为：

在 main 中验证纯函数Rust 2021
fn normalize_username(raw: &str) -> String {
    raw.trim().to_lowercase()
}

fn parse_age(raw: &str) -> Result<u8, String> {
    let age: u8 = raw
        .trim()
        .parse()
        .map_err(|_| format!("不是合法年龄: {raw}"))?;
    if age == 0 || age > 130 {
        return Err(format!("年龄超出范围: {age}"));
    }
    Ok(age)
}

fn main() {
    assert_eq!(normalize_username("  Ada "), "ada");
    assert_eq!(parse_age("36"), Ok(36));
    assert!(parse_age("abc").is_err());
    assert!(parse_age("200").is_err());
    assert!(parse_age("0").is_err());
    println!("全部断言通过");
}

常见错误与工程建议 ​

  • 只测正常路径。每个返回 Result 的函数至少覆盖一个错误分支，边界值（0、空字符串、最大值）优先于普通输入。
  • 测试依赖当前时间、随机数、网络或真实数据库，会产生偶发失败（flaky test）。把这些依赖作为参数注入，测试中传入固定值。
  • 测试之间共享可变全局状态，单线程运行时通过，并行运行时随机失败。每个测试自己构造所需数据。
  • should_panic 不写 expected，任何 panic 都算通过，容易掩盖真正的错误。
  • 测试名用 parses_empty_input_as_error 这类行为描述，失败列表本身就是一份问题清单。
  • CI 中固定执行以下门禁：
bash
cargo fmt --all -- --check
cargo clippy --all-targets -- -D warnings
cargo test

练习

实现 parse_port(input: &str) -> Result<u16, String>：先去除首尾空白，拒绝空输入、非数字、0 与超出 u16 范围的值，错误信息包含原始输入。为它编写至少 6 条断言，覆盖正常值与各类错误。

参考答案
为 parse_port 补齐断言Rust 2021
fn parse_port(raw: &str) -> Result<u16, String> {
    let text = raw.trim();
    if text.is_empty() {
        return Err("端口不能为空".to_string());
    }
    let port: u16 = text
        .parse()
        .map_err(|_| format!("端口不是合法数字: {text}"))?;
    if port == 0 {
        return Err(format!("端口必须大于 0: {text}"));
    }
    Ok(port)
}

fn main() {
    assert_eq!(parse_port(" 8080 "), Ok(8080));
    assert_eq!(parse_port("65535"), Ok(65535));
    assert_eq!(parse_port("0"), Err("端口必须大于 0: 0".to_string()));
    assert!(parse_port("70000").is_err());
    assert!(parse_port("http").is_err());
    assert!(parse_port("   ").is_err());
    println!("parse_port 的全部断言通过");
}

小结 ​

  • #[test] 标记测试函数，panic 即失败；assert_eq!、assert! 负责表达期望。
  • 单元测试与被测代码同文件，用 #[cfg(test)] 隔离；集成测试放在 tests/，只能访问公开 API。
  • 文档测试会随 cargo test 运行，能防止示例与实现脱节。
  • cargo fmt --check、cargo clippy -D warnings、cargo test 构成最小 CI 门禁。
