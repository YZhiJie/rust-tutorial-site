宏、unsafe 与 FFI ​

学习目标

  • 用 macro_rules! 编写声明宏（declarative macro），掌握重复匹配与可选分隔符
  • 理解宏的卫生性（hygiene）与过程宏（procedural macro）的基本分类
  • 明确 unsafe 的安全契约、裸指针（raw pointer）与未定义行为（undefined behavior）
  • 通过 extern "C" 理解外部函数接口（FFI）的边界与责任

宏能解决什么问题 ​

函数要求参数类型与数量在调用点已经确定，而有些重复无法用函数表达：println! 接受可变数量的参数并做格式检查，vec! 接受任意数量的元素，derive 自动生成 trait 实现。这些都由宏（macro）在编译期生成代码。

Rust 的宏分两类：

  • 声明宏（declarative macro，macro_rules!）：按语法模式匹配并展开，适合小型代码生成与 DSL；
  • 过程宏（procedural macro）：用 Rust 代码处理 token 流，分为派生宏（derive）、属性宏（attribute）与函数式宏（function-like）。

宏在编译期展开，运行时没有额外调用开销，但错误信息定位会比普通函数更困难。

macro_rules! 与重复 ​

声明宏由若干规则组成，每条规则左边是匹配模式，右边是展开结果。$name:片段类型 用于捕获语法片段，常见类型有 expr、ident、ty、pat、tt。$(...)* 表示重复匹配零次或多次，$(...),* 表示以逗号分隔。

用重复匹配实现求和宏Rust 2021
macro_rules! sum {
    ($($x:expr),* $(,)?) => {{
        let mut total = 0;
        $(total += $x;)*
        total
    }};
}

fn main() {
    println!("{}", sum!(1, 2, 3, 4));
    println!("{}", sum!(5, 6,));
    println!("{}", sum!());
}

三层花括号 {{ ... }} 让展开结果成为一个表达式块，避免在调用点引入多余的作用域问题。$(,)? 允许末尾多余的逗号，sum!() 则命中零次重复。

卫生性 ​

宏展开的代码与调用点代码共享作用域，因此宏内部引入的变量可能意外遮蔽调用方的同名变量。卫生性（hygiene）让宏定义的标识符与调用点标识符处于不同语法上下文，从而互不干扰。

宏的卫生性Rust 2021
macro_rules! make_value {
    () => {
        let value = 10;
    };
}

fn main() {
    let value = 1;
    make_value!();
    println!("{value}");
}

过程宏概览 ​

过程宏必须定义在单独的 proc-macro 类型 crate 中，输入输出都是 TokenStream，通常借助 syn 与 quote 解析和生成代码。三类过程宏的用途不同：

类型调用形式典型用途
派生宏#[derive(MyTrait)]为结构体、枚举生成 trait 实现
属性宏#[my_attr]改写被标注的项，如路由、测试属性
函数式宏my_macro!(...)类似声明宏，但可用完整 Rust 代码处理输入

日常使用的 #[derive(Debug, Clone, PartialEq)] 就是标准库提供的派生宏。过程宏不能在普通二进制 crate 中定义，因此本站的在线示例不演示其实现。

unsafe 与安全契约 ​

unsafe 不是“关闭安全检查”的开关。借用检查、类型检查与生命周期检查照常执行，它只是额外允许五类操作：解引用裸指针、调用 unsafe 函数、访问或修改可变静态变量、实现 unsafe trait、访问联合体（union）字段。

使用 unsafe 意味着开发者向编译器承诺某些前置条件成立，这就是安全契约（safety contract）。违反契约会产生未定义行为，编译器不再保证程序语义。自定义 unsafe fn 时，应在其文档注释中写明 # Safety 要求。

裸指针与 unsafe 函数Rust 2021
/// # Safety
/// `ptr` 必须指向一个有效且对齐的 `i32`。
unsafe fn read_raw(ptr: *const i32) -> i32 {
    unsafe { *ptr }
}

fn main() {
    let mut value = 41;
    let ptr = &mut value as *mut i32;

    unsafe {
        *ptr += 1;
    }

    let result = unsafe { read_raw(&value) };
    println!("结果: {result}");
}

extern "C" 与 FFI ​

FFI（外部函数接口，foreign function interface）让 Rust 调用其他语言的函数，或把 Rust 函数导出给其他语言。调用 C 函数时，用 extern "C" 块声明签名，再在 unsafe 块中调用；链接由构建系统或 #[link] 属性负责。

rust
extern "C" {
    fn abs(input: i32) -> i32;
}

fn main() {
    let value = unsafe { abs(-42) };
    println!("{value}");
}

abs 来自平台 C 标准库。真实项目往往需要链接自定义 C 库，涉及构建脚本、头文件与目标平台差异，因此这里只作签名与调用方式的说明，不放入在线示例。Rust 2024 edition 要求写成 unsafe extern "C" { ... }，因为声明本身也承担了“签名可信”的契约。

跨边界传递数据时，只能使用 FFI 安全的类型：整数、浮点数、裸指针、#[repr(C)] 结构体。String、Vec 与 trait 对象的内存布局不受保证，应传递指针与长度，并明确由哪一侧释放。C 字符串还需借助 std::ffi::CStr、CString 转换，并处理空指针与编码问题。

练习 ​

练习

编写 min! 宏，接受一个或多个表达式，返回其中的最小值，并支持末尾多余逗号。分别用 min!(3, 1, 4, 1, 5) 与 min!(9) 测试。

参考答案
支持重复与尾逗号的 min! 宏Rust 2021
macro_rules! min {
    ($first:expr $(, $rest:expr)* $(,)?) => {{
        let mut result = $first;
        $(result = result.min($rest);)*
        result
    }};
}

fn main() {
    println!("{}", min!(3, 1, 4, 1, 5));
    println!("{}", min!(9));
}

小结 ​

  • macro_rules! 通过模式匹配与 $(...)* 重复在编译期生成代码。
  • 卫生性避免宏内部标识符污染调用点；跨 crate 导出宏时使用 $crate。
  • 过程宏分为派生、属性与函数式三类，必须放在独立的 proc-macro crate。
  • unsafe 只解锁特定操作，安全契约仍由开发者负责，违反契约会导致未定义行为。
  • extern "C" 定义 FFI 边界，类型布局、内存所有权与释放责任都必须在两侧约定一致。
