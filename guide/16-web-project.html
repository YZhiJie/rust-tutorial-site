实战：axum Web 服务 ​

学习目标

  • 用 axum 0.8 定义路由（routing）与处理器（handler）
  • 用 serde 1.x 完成 JSON 的序列化（serialization）与反序列化（deserialization）
  • 用共享状态（state）实现线程安全的内存存储
  • 掌握错误响应、接口测试与部署的基本做法

项目需求 ​

实现一个待办事项（todo）HTTP API，数据保存在进程内存中，不引入数据库。

方法路径作用状态码
GET/todos列出条目200
POST/todos创建条目201
GET/todos/{id}查询单条200
PATCH/todos/{id}切换完成状态200
DELETE/todos/{id}删除条目204

标题为空返回 400，资源不存在返回 404；GET /health 用于部署探活；并发请求必须安全访问共享数据；进程重启后数据丢失。

分步实现 ​

第一步：定义数据模型与共享状态 ​

rust
use serde::{Deserialize, Serialize};
use std::sync::{Arc, Mutex};

#[derive(Debug, Clone, Serialize)]
struct Todo { id: u64, title: String, done: bool }
#[derive(Debug, Deserialize)]
struct CreateTodo { title: String }
#[derive(Default)]
struct Store { next_id: u64, todos: Vec<Todo> }

impl Store {
    fn create(&mut self, title: &str) -> Todo {
        self.next_id += 1;
        let todo = Todo { id: self.next_id, title: title.to_string(), done: false };
        self.todos.push(todo.clone());
        todo
    }
    fn find(&self, id: u64) -> Option<&Todo> {
        self.todos.iter().find(|todo| todo.id == id)
    }
    fn delete(&mut self, id: u64) -> bool {
        let before = self.todos.len();
        self.todos.retain(|todo| todo.id != id);
        self.todos.len() != before
    }
}
#[derive(Clone, Default)]
struct AppState { store: Arc<Mutex<Store>> }

Todo 只实现 Serialize，CreateTodo 只实现 Deserialize，客户端因此无法伪造 id 与 done。AppState 实现 Clone，每个请求拿到一份状态副本；Arc 让副本指向同一块数据，Mutex 保证同一时刻只有一个处理器修改它。std::sync::Mutex 的守卫不是 Send，不能跨 .await 持有；本项目临界区不含挂起点，可以使用标准库锁，若需跨挂起点持锁，应改用 tokio::sync::Mutex。

第二步：编写处理器 ​

rust
use axum::{extract::{Path, State}, http::StatusCode, Json};

async fn list_todos(State(state): State<AppState>) -> Json<Vec<Todo>> {
    Json(state.store.lock().expect("锁被污染").todos.clone())
}

async fn create_todo(
    State(state): State<AppState>,
    Json(input): Json<CreateTodo>,
) -> Result<(StatusCode, Json<Todo>), StatusCode> {
    let title = input.title.trim();
    if title.is_empty() { return Err(StatusCode::BAD_REQUEST); }
    let mut store = state.store.lock().expect("锁被污染");
    Ok((StatusCode::CREATED, Json(store.create(title))))
}
async fn get_todo(State(state): State<AppState>, Path(id): Path<u64>) -> Result<Json<Todo>, StatusCode> {
    let store = state.store.lock().expect("锁被污染");
    store.find(id).cloned().map(Json).ok_or(StatusCode::NOT_FOUND)
}
async fn toggle_todo(State(state): State<AppState>, Path(id): Path<u64>) -> Result<Json<Todo>, StatusCode> {
    let mut store = state.store.lock().expect("锁被污染");
    let todo = store.todos.iter_mut().find(|todo| todo.id == id).ok_or(StatusCode::NOT_FOUND)?;
    todo.done = !todo.done;
    Ok(Json(todo.clone()))
}
async fn delete_todo(State(state): State<AppState>, Path(id): Path<u64>) -> StatusCode {
    let mut store = state.store.lock().expect("锁被污染");
    if store.delete(id) { StatusCode::NO_CONTENT } else { StatusCode::NOT_FOUND }
}

只有最后一个参数可以消费请求体，因此 Json 必须放在 State、Path 之后。Path<u64> 解析失败自动返回 400；Json 解析失败返回 400 或 422，内容类型不匹配返回 415。返回值使用 Result<T, StatusCode> 时，Ok 走正常响应，Err 直接生成对应状态码。axum 0.8 的路径参数是花括号语法 {id}，旧写法 :id 不再匹配。

第三步：组装路由并启动 ​

rust
use axum::{routing::get, Router};
async fn health() -> &'static str { "ok" }

fn app(state: AppState) -> Router {
    Router::new()
        .route("/health", get(health))
        .route("/todos", get(list_todos).post(create_todo))
        .route("/todos/{id}", get(get_todo).patch(toggle_todo).delete(delete_todo))
        .with_state(state)
}

#[tokio::main]
async fn main() {
    let listener = tokio::net::TcpListener::bind("127.0.0.1:3000").await.expect("bind 失败");
    println!("listening on http://127.0.0.1:3000");
    axum::serve(listener, app(AppState::default())).await.expect("serve 失败");
}

第四步：用标准库模拟核心逻辑 ​

真实服务由框架解析 HTTP，核心仍然是「操作数据 + 映射状态码」。下面的示例只依赖标准库，复现存储与状态码的变化过程。

模拟待办存储与状态码Rust 2021
use std::collections::HashMap;

#[derive(Default)]
struct Store {
    next_id: u64,
    items: HashMap<u64, (String, bool)>,
}

impl Store {
    fn create(&mut self, title: &str) -> u64 {
        self.next_id += 1;
        self.items.insert(self.next_id, (title.into(), false));
        self.next_id
    }
    fn toggle(&mut self, id: u64) -> bool {
        match self.items.get_mut(&id) {
            Some((_, done)) => { *done = !*done; true }
            None => false,
        }
    }
    fn delete(&mut self, id: u64) -> bool {
        self.items.remove(&id).is_some()
    }
}
fn main() {
    let mut store = Store::default();
    let id = store.create("写文档");
    store.create("补测试");
    println!("POST /todos -> 201 id={id}");
    println!("GET /todos -> 200 count={}", store.items.len());

    let status = if store.toggle(id) { 200 } else { 404 };
    println!("PATCH /todos/{id} -> {status} done={}", store.items[&id].1);
    println!("DELETE /todos/2 -> {}", if store.delete(2) { 204 } else { 404 });
    println!("DELETE /todos/2 再次 -> {}", if store.delete(2) { 204 } else { 404 });
}

测试与部署 ​

处理器是普通异步函数，测试中可以直接调用，无需启动 TCP 服务：

rust
#[cfg(test)]
mod tests {
    use super::*;

    #[tokio::test]
    async fn create_returns_201() {
        let state = AppState::default();
        let input = Json(CreateTodo { title: "写文档".into() });
        let (status, Json(todo)) = create_todo(State(state.clone()), input).await.unwrap();
        assert_eq!(status, StatusCode::CREATED);
        assert_eq!(todo.id, 1);
        assert_eq!(state.store.lock().unwrap().todos.len(), 1);
    }
}

练习

增加 PUT /todos/{id} 全量更新标题并重置完成状态，以及 GET /todos?done=true 过滤。保持 400/404 的错误语义。

参考答案

新增 #[derive(Deserialize)] struct ListQuery { done: Option<bool> }，列表处理器追加 Query(query): Query<ListQuery>，用 query.done.map_or(true, |done| todo.done == done) 过滤。更新处理器注册为 .put(replace_todo)，先校验空标题返回 400，再用 iter_mut().find(...) 取可变引用，取不到返回 404。

小结 ​

  • axum 0.8 用 Router 组合路由，用提取器解析路径、状态与 JSON 请求体。
  • 0.8 的路径参数是 {id}，迁移旧代码时需替换 :id。
  • Arc<Mutex<T>> 是进程内共享状态的最小方案，临界区不要跨 .await。
  • 处理器返回 Result<_, StatusCode> 即可把业务失败映射为 HTTP 状态码。
