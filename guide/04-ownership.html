所有权、借用与生命周期 ​

学习目标

  • 理解栈（stack）与堆（heap）的分工，以及所有权（ownership）的三条规则
  • 区分移动（move）、克隆（clone）与 Copy，读懂「use of moved value」错误
  • 掌握共享借用与可变借用的互斥规则，理解 NLL 如何缩短借用作用域
  • 会为函数与结构体编写基础的生命周期（lifetime）标注

问题背景：没有垃圾回收也要内存安全 ​

Rust 不依赖垃圾回收器（garbage collector），也不要求手动 free。它用所有权在编译期回答三个问题：这块堆内存归谁负责释放、谁能读取、谁能修改。编译器据此插入释放代码并拒绝悬垂引用，代价是开发者需要理解借用检查（borrow checking）的规则。

栈与堆 ​

栈（stack）存放编译期已知大小的数据，后进先出，分配与释放只是移动栈指针。堆（heap）在运行时按需分配，分配器返回地址，访问需要经过指针。

String 是典型的「栈上元数据 + 堆上数据」：

text

┌───────────────┐
│ ptr ──────────┼──────► "hello"（5 字节）
│ len = 5       │
│ capacity = 5  │
└───────────────┘

栈上部分负责记录位置、长度与容量，堆上部分存放实际字节。赋值 let s2 = s1; 时，如果逐字节复制栈上元数据，就会有两个指针指向同一块堆内存；Rust 选择让 s1 失效，避免双重释放（double free）。

所有权三条规则 ​

  1. 每个值有且只有一个所有者（owner）。
  2. 同一时刻只能有一个所有者。
  3. 所有者离开作用域时，值被丢弃（drop），堆内存随之释放。
移动、克隆与 CopyRust 2021
fn main() {
    let s1 = String::from("ownership");
    let s2 = s1; // 所有权从 s1 移动到 s2
    // println!("{s1}"); // error[E0382]: borrow of moved value: `s1`
    println!("s2 = {s2}");

    let s3 = s2.clone(); // 显式深拷贝堆数据
    println!("s2 = {s2}，s3 = {s3}");

    let a = 42;
    let b = a; // i32 实现 Copy，按位复制
    println!("a = {a}，b = {b}");
}

  • 移动（move）：非 Copy 类型在赋值、传参、返回时转移所有权，原变量不能再使用。
  • 克隆（clone）：显式复制堆数据，原变量与新变量各自拥有独立内存；可能代价较高。
  • Copy：整数、浮点、bool、char、共享引用，以及全部由 Copy 类型组成的元组与数组。实现 Copy 的类型同时必须实现 Clone，复制是隐式且廉价的。

所有权也会随函数调用转移：fn take(text: String) 会接管 text，函数结束时将其释放；fn measure(text: &str) 只借用，调用后原值仍可用。

引用与借用 ​

引用（reference）让函数访问值而不取得所有权。&T 是共享引用（shared reference），&mut T 是可变引用（mutable reference）。创建引用的行为称为借用（borrow）。

借用检查的核心规则：在任意时刻，对同一个值要么存在任意多个 &T，要么存在唯一一个 &mut T，两者不能同时存在。

共享借用、可变借用与 NLLRust 2021
fn sum(values: &[i32]) -> i32 {
    values.iter().sum()
}

fn main() {
    let mut data = vec![1, 2, 3];
    println!("sum = {}，data = {data:?}", sum(&data));

    let first = &data[0];
    // data.push(4); // error[E0502]：仍被不可变借用
    println!("first = {first}");
    data.push(4); // NLL：first 最后一次使用后借用结束，此处合法
    println!("data = {data:?}");

    let last = &mut data;
    last.push(5);
    // let other = &mut data; // error[E0499]：可变借用不能同时存在两个
    println!("data = {data:?}");
}

非词法生命周期（non-lexical lifetimes，NLL）从 Rust 2018 起默认启用：借用的有效范围到最后一次使用为止，而不是外层花括号结束。因此把 data.push(4) 放在 first 最后一次使用之后是合法的；放在之前则冲突。

悬垂引用 ​

悬垂引用（dangling reference）指向已经释放的内存。Rust 在编译期拒绝这种代码：

rust
fn dangling<'a>() -> &'a String {
    let s = String::from("temp");
    &s // error[E0515]: cannot return reference to local variable `s`
}

fn main() {
    let value = dangling();
    println!("{value}");
}

生命周期标注 ​

生命周期（lifetime）标注用 'a 这样的名称表示「引用至少存活多久」。标注不改变值的生命周期，只告诉编译器多个引用之间的关系。

当函数从多个输入引用中返回一个引用时，编译器无法自动判断返回值跟随哪个输入，需要显式标注：

生命周期标注：返回较长者Rust 2021
fn longest<'a>(a: &'a str, b: &'a str) -> &'a str {
    if a.len() >= b.len() { a } else { b }
}

fn main() {
    let x = String::from("long string");
    {
        let y = String::from("short");
        println!("longest = {}", longest(&x, &y)); // y 在此作用域内有效
    }
    println!("longest = {}", longest(&x, &x));
}

'a 表示返回引用的有效期不超过 a 与 b 中较短的那个。调用处必须保证两个实参在结果使用期间都存活。省略规则（elision）覆盖了常见情形：只有一个输入引用时，返回值继承它的生命周期；方法签名中的 &self 也把生命周期传给返回值。

结构体持有引用时同样需要标注：

结构体持有引用Rust 2021
struct Excerpt<'a> {
    text: &'a str,
}

fn main() {
    let novel = String::from("第一章：所有权\n第二章：借用");
    let excerpt = Excerpt { text: &novel };
    println!("首行 = {}", excerpt.text.lines().next().unwrap_or(""));
}

小结 ​

  • 栈存放固定大小的数据，堆存放运行时分配的数据；String 的元数据在栈上，字节在堆上。
  • 每个值只有一个所有者，所有者离开作用域时值被 drop。
  • 非 Copy 类型在赋值与传参时移动；clone 显式复制堆数据。
  • 同一时刻只能有多个共享借用或一个可变借用；NLL 把借用结束点提前到最后一次使用。
  • 生命周期标注描述引用之间的关系，不能延长值的存活时间；结构体持有引用时必须标注。
