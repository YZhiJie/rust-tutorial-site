并发编程 ​

学习目标

  • 用 thread::spawn、move 闭包与 join 创建并回收线程（thread）
  • 用 mpsc 通道（channel）在线程间传递消息
  • 用 Arc<Mutex<T>> 安全共享可变状态
  • 理解 Send、Sync 的约束，以及 thread::scope 的借用能力

为什么需要并发 ​

并发（concurrency）让多个任务在时间上重叠执行：等待 I/O 时 CPU 可以处理其他工作，多核机器也能同时运行多个计算任务。代价是共享数据可能出现数据竞争（data race），即两个线程同时访问同一内存且至少一个在写入。

多数语言把数据竞争留到运行时排查。Rust 把“能否跨线程移动”“能否跨线程共享”编码进类型系统，由编译器在编译期拒绝不安全的共享方式。这一章的所有工具都建立在这两个标记 trait（marker trait）之上。

线程、move 闭包与 join ​

std::thread::spawn 接受一个满足 FnOnce() + Send + 'static 的闭包，返回 JoinHandle<T>。move 把捕获变量的所有权交给闭包，从而满足 'static 要求；join 阻塞当前线程并取得子线程的返回值。

多线程分段求和Rust 2021
use std::thread;

fn main() {
    let handles: Vec<_> = (1..=4u64)
        .map(|i| {
            thread::spawn(move || {
                let sum: u64 = (1..=i * 1000).sum();
                (i, sum)
            })
        })
        .collect();

    let mut total = 0;
    for handle in handles {
        let (i, sum) = handle.join().unwrap();
        println!("线程 {i} 求和: {sum}");
        total += sum;
    }
    println!("总计: {total}");
}

若不调用 join，主线程结束时会直接退出进程，子线程可能来不及完成。join 返回 Result：子线程 panic 时，错误会在这里被观察到。

消息传递：mpsc 通道 ​

“不要通过共享内存来通信，而要通过通信来共享内存。”std::sync::mpsc 提供多生产者、单消费者（multi-producer, single-consumer）通道。发送端 Sender<T> 可以克隆，接收端 Receiver<T> 独占。

生产者与消费者Rust 2021
use std::sync::mpsc;
use std::thread;

fn main() {
    let (tx, rx) = mpsc::channel();

    let producer = thread::spawn(move || {
        for i in 1..=3 {
            tx.send(format!("消息 {i}")).unwrap();
        }
    });

    for message in rx {
        println!("收到: {message}");
    }

    producer.join().unwrap();
}

for message in rx 会持续阻塞，直到所有 Sender 被丢弃、通道关闭。生产者线程结束时 tx 随之析构，循环因此退出。send 在接收端已关闭时返回 Err，所以需要处理或 unwrap。

共享状态：Arc 与 Mutex ​

多个线程需要修改同一份数据时，用 Arc<T> 提供跨线程的共享所有权，用 Mutex<T> 保证同一时刻只有一个线程能访问内部值。lock() 返回 MutexGuard，离开作用域时自动解锁。

Arc<Mutex<T>> 计数Rust 2021
use std::sync::{Arc, Mutex};
use std::thread;

fn main() {
    let counter = Arc::new(Mutex::new(0));
    let mut handles = Vec::new();

    for _ in 0..4 {
        let counter = Arc::clone(&counter);
        handles.push(thread::spawn(move || {
            for _ in 0..100 {
                let mut value = counter.lock().unwrap();
                *value += 1;
            }
        }));
    }

    for handle in handles {
        handle.join().unwrap();
    }

    println!("最终计数: {}", *counter.lock().unwrap());
}

Arc 的克隆只增加原子引用计数。Mutex 保证互斥（mutual exclusion），MutexGuard 的 DerefMut 允许直接修改内部值。若某个线程在持锁时 panic，互斥锁会被标记为中毒（poisoned），后续 lock 返回 Err。

作用域线程：借用栈上的数据 ​

thread::spawn 要求 'static，因为它无法证明借用会活多久。std::thread::scope 创建的作用域线程（scoped thread）保证在作用域结束前全部 join，因此可以安全借用栈上的局部变量。

用 scope 借用局部数据Rust 2021
use std::thread;

fn main() {
    let data = vec![1, 2, 3, 4];
    let mut results = vec![0; data.len()];

    thread::scope(|scope| {
        for (i, slot) in results.iter_mut().enumerate() {
            let value = &data[i];
            scope.spawn(move || {
                *slot = *value * 2;
            });
        }
    });

    println!("{results:?}");
}

Send 与 Sync ​

Send 表示类型的所有权可以安全地移动到另一个线程，Sync 表示 &T 可以安全地被多个线程共享。Rc<T> 没有实现 Send；Arc<T> 在 T: Send + Sync 时同时实现 Send 与 Sync，Mutex<T> 在 T: Send 时实现 Sync，RefCell<T> 没有实现 Sync。

两者都是自动 trait（auto trait），由编译器根据字段自动推导。只有确认底层实现满足线程安全时，才允许手写 unsafe impl Send/Sync。

练习 ​

练习

使用 thread::scope 把 1 到 1000 的整数按块分给 4 个线程并行求和，再与单线程结果比较。

参考答案
作用域线程并行求和Rust 2021
use std::thread;

fn parallel_sum(data: &[i32], parts: usize) -> i32 {
    let chunk = data.len().div_ceil(parts);
    let mut total = 0;

    thread::scope(|scope| {
        let handles: Vec<_> = data
            .chunks(chunk)
            .map(|slice| scope.spawn(|| slice.iter().sum::<i32>()))
            .collect();

        for handle in handles {
            total += handle.join().unwrap();
        }
    });

    total
}

fn main() {
    let data: Vec<i32> = (1..=1000).collect();
    let sum = parallel_sum(&data, 4);

    println!("并行求和: {sum}");
    println!("校验: {}", data.iter().sum::<i32>());
}

小结 ​

  • thread::spawn 的闭包需要 Send + 'static，move 用于转移捕获值的所有权。
  • mpsc 通道以消息传递代替共享内存，所有发送端销毁后接收循环结束。
  • Arc<Mutex<T>> 是跨线程共享可变状态的默认组合，注意锁的粒度与中毒。
  • thread::scope 允许借用局部数据，并在作用域结束时自动 join。
