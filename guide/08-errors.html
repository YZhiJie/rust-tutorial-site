错误处理 ​

学习目标

  • 分清 panic! 与 Result 的边界，理解 unwrap/expect 的代价
  • 用 ? 传播错误，并理解它自动执行的 From 转换
  • 定义自定义错误枚举，实现 Display 与 std::error::Error
  • 使用 Box<dyn Error> 统一错误类型，并用 Option 组合子处理缺失值

问题背景 ​

程序失败分为两类：代码缺陷（越界、违反不变量）与预期内的外部失败（文件不存在、输入格式错误、网络超时）。Rust 用 panic! 表达前者，用 Result<T, E> 表达后者。混用会导致两种极端：到处 unwrap 让程序脆弱，或把所有失败都塞进 Result，让调用方疲于处理不可能发生的情况。

panic 与 Result 的边界 ​

panic! 会展开栈（unwind）并终止当前线程，适合“继续执行已无意义”的场景。Result 把失败作为普通值返回，调用方可以选择处理、转换或继续传播。unwrap() 在 Err/None 时 panic，expect("...") 额外附带说明；二者适合原型、测试和已确认不会失败的位置，库代码与用户输入路径应优先返回 Result。

Result 与 ? 传播 ​

Result<T, E> 只有 Ok(T) 与 Err(E)。? 在成功时取出值，失败时提前返回 Err，返回前通过 From::from 把错误转换成当前函数的错误类型，因此函数签名必须能容纳该错误。

自定义错误、Display 与 ?Rust 2021
use std::num::ParseIntError;
#[derive(Debug)]
enum ConfigError {
    MissingField(&'static str),
    InvalidNumber { field: &'static str, source: ParseIntError },
}
impl std::fmt::Display for ConfigError {
    fn fmt(&self, f: &mut std::fmt::Formatter<'_>) -> std::fmt::Result {
        match self {
            ConfigError::MissingField(field) => write!(f, "缺少字段：{field}"),
            ConfigError::InvalidNumber { field, source } => write!(f, "字段 {field} 不是合法数字：{source}"),
        }
    }
}
impl std::error::Error for ConfigError {}
fn parse_port(raw: &str) -> Result<u16, ConfigError> {
    raw.trim()
        .parse::<u16>()
        .map_err(|source| ConfigError::InvalidNumber { field: "port", source })
}
fn build_address(host: &str, raw_port: &str) -> Result<String, ConfigError> {
    if host.trim().is_empty() {
        return Err(ConfigError::MissingField("host"));
    }
    let port = parse_port(raw_port)?;
    Ok(format!("{}:{}", host.trim(), port))
}
fn main() {
    match build_address("127.0.0.1", "8080") {
        Ok(address) => println!("地址: {address}"),
        Err(error) => println!("配置错误: {error}"),
    }
    match build_address("127.0.0.1", "abc") {
        Ok(address) => println!("地址: {address}"),
        Err(error) => println!("配置错误: {error}"),
    }
}

parse_port 的 map_err 把标准库错误包装为自定义变体，build_address 中的 ? 再把它向上返回。Display 面向用户输出，空实现的 Error 让它可与其他错误组合；若需暴露底层错误，可覆盖 source。

Box<dyn Error> 统一错误类型 ​

函数可能返回多种错误、且调用方不需要区分类型时，可以返回 Box<dyn Error>。? 会把任何实现了 Error 的错误装箱，省去逐一定义 From 的样板代码。main 也可以返回 Result<(), Box<dyn Error>>，此时 Err 会打印 Debug 表示并以非零状态码退出。

Box<dyn Error> 与 ?Rust 2021
use std::error::Error;
fn parse_all(items: &[&str]) -> Result<Vec<i32>, Box<dyn Error>> {
    let mut values = Vec::new();
    for item in items {
        values.push(item.trim().parse::<i32>()?);
    }
    Ok(values)
}
fn main() -> Result<(), Box<dyn Error>> {
    let values = parse_all(&["1", " 2 ", "3"])?;
    println!("解析结果: {values:?}");
    match parse_all(&["1", "x", "3"]) {
        Ok(values) => println!("不应到达: {values:?}"),
        Err(error) => println!("解析失败: {error}"),
    }
    Ok(())
}

Option 组合子 ​

Option 用于“没有值不算错误”的场景。常用组合子有 map、and_then、unwrap_or、unwrap_or_else、ok_or 与 filter。在返回 Option 的函数中，? 会在 None 时提前返回 None；需要把缺失转换为错误时使用 ok_or 或 ok_or_else。

Option 组合子Rust 2021
fn parse_positive(raw: &str) -> Option<i32> {
    let value = raw.trim().parse::<i32>().ok()?;
    if value > 0 { Some(value) } else { None }
}
fn main() {
    let values = [
        parse_positive("42"),
        parse_positive("-1"),
        parse_positive("abc"),
    ];
    for value in values.iter().copied() {
        println!("{value:?} -> {}", value.map(|v| v * 2).unwrap_or(0));
    }
    let valid: Vec<i32> = values.iter().flatten().copied().collect();
    println!("有效值: {valid:?}");
    println!("默认值: {}", parse_positive("nope").unwrap_or_else(|| 7));
    println!("偶数检查: {:?}", parse_positive("10").filter(|v| v % 2 == 0));
}

练习

解析形如 host=127.0.0.1;port=8080;retries=3 的配置字符串，返回包含 host、port、retries 的结构体。定义错误枚举区分缺少字段、未知字段与数字格式错误，并实现 Display 与 Error。

参考答案
参考答案：解析配置字符串Rust 2021
use std::collections::HashMap;
use std::num::ParseIntError;
#[derive(Debug, PartialEq)]
struct Config { host: String, port: u16, retries: u32 }
#[derive(Debug)]
enum ConfigError {
    MissingField(&'static str),
    UnknownField(String),
    InvalidNumber { field: String, source: ParseIntError },
}
impl std::fmt::Display for ConfigError {
    fn fmt(&self, f: &mut std::fmt::Formatter<'_>) -> std::fmt::Result {
        match self {
            Self::MissingField(field) => write!(f, "缺少字段：{field}"),
            Self::UnknownField(field) => write!(f, "未知字段：{field}"),
            Self::InvalidNumber { field, source } => write!(f, "字段 {field} 的数值无效：{source}"),
        }
    }
}
impl std::error::Error for ConfigError {}
fn parse_config(input: &str) -> Result<Config, ConfigError> {
    let mut fields: HashMap<&str, &str> = HashMap::new();
    for pair in input.split(';') {
        let pair = pair.trim();
        if pair.is_empty() { continue; }
        let (key, value) = pair
            .split_once('=')
            .ok_or_else(|| ConfigError::UnknownField(pair.to_string()))?;
        fields.insert(key.trim(), value.trim());
    }

    let host = fields.get("host").ok_or(ConfigError::MissingField("host"))?.to_string();
    let port = fields.get("port").ok_or(ConfigError::MissingField("port"))?
        .parse::<u16>()
        .map_err(|source| ConfigError::InvalidNumber { field: "port".into(), source })?;
    let retries = fields.get("retries").ok_or(ConfigError::MissingField("retries"))?
        .parse::<u32>()
        .map_err(|source| ConfigError::InvalidNumber { field: "retries".into(), source })?;

    for key in fields.keys() {
        if !matches!(*key, "host" | "port" | "retries") {
            return Err(ConfigError::UnknownField(key.to_string()));
        }
    }
    Ok(Config { host, port, retries })
}

fn main() {
    match parse_config("host=127.0.0.1;port=8080;retries=3") {
        Ok(config) => println!("{config:?}"),
        Err(error) => println!("错误: {error}"),
    }
    match parse_config("host=localhost;port=abc") {
        Ok(config) => println!("{config:?}"),
        Err(error) => println!("错误: {error}"),
    }
}

小结 ​

  • panic! 处理不可恢复的缺陷，Result 处理可预期的失败。
  • unwrap/expect 会在失败时 panic，只应出现在确认安全或原型的场景。
  • ? 提前返回错误，并通过 From 自动转换错误类型。
  • 自定义错误需要 Debug、Display 与 std::error::Error 三个实现。
  • Box<dyn Error> 适合混合错误；Option 组合子处理缺失值，需要错误语义时用 ok_or。
