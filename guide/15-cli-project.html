实战：CLI 工具 ​

学习目标

  • 用 bin + lib 结构组织命令行项目（CLI，command-line interface）
  • 用 clap 4 定义参数与子命令（subcommand）
  • 处理标准输入（stdin）、文件读写与错误传播（error propagation）
  • 编写集成测试并产出 release 可执行文件

问题背景 ​

命令行工具是最常见的 Rust 交付形态：逻辑集中、依赖少、易于组合。它与普通程序的区别在于输入来自参数与标准流，失败必须给出可读信息和非零退出码，行为还要能被脚本稳定调用。把全部代码写进 main.rs 可以快速跑通，但参数解析、业务逻辑和文件访问混在一起后，测试只能靠启动进程。更合适的做法是：lib.rs 承载可测试的核心逻辑，main.rs 只负责解析参数并把错误交给运行时。

项目结构 ​

text
todo/{Cargo.toml, src/{lib.rs, main.rs}, tests/cli.rs}

核心逻辑：src/lib.rs ​

rust
use std::{fs, io, path::Path};

#[derive(Debug, Clone, PartialEq, Eq)]
pub struct Task { pub text: String, pub done: bool }

pub fn parse_line(line: &str) -> Task {
    match line.strip_prefix("[x] ") {
        Some(text) => Task { text: text.into(), done: true },
        None => Task { text: line.strip_prefix("[ ] ").unwrap_or(line).into(), done: false },
    }
}

pub fn render(task: &Task) -> String {
    format!("{} {}", if task.done { "[x]" } else { "[ ]" }, task.text)
}

pub fn load(path: &Path) -> io::Result<Vec<Task>> {
    match fs::read_to_string(path) {
        Ok(text) => Ok(text.lines().filter(|l| !l.trim().is_empty()).map(parse_line).collect()),
        Err(e) if e.kind() == io::ErrorKind::NotFound => Ok(Vec::new()),
        Err(e) => Err(e),
    }
}

pub fn save(path: &Path, tasks: &[Task]) -> io::Result<()> {
    let text: String = tasks.iter().map(|t| format!("{}\n", render(t))).collect();
    fs::write(path, text)
}

pub fn add(tasks: &mut Vec<Task>, text: &str) -> usize {
    tasks.push(Task { text: text.into(), done: false });
    tasks.len() - 1
}

fn index_of(tasks: &[Task], number: usize) -> Result<usize, String> {
    let index = number.checked_sub(1).ok_or("序号从 1 开始")?;
    if index >= tasks.len() {
        return Err(format!("序号 {number} 越界，当前共 {} 条", tasks.len()));
    }
    Ok(index)
}

pub fn mark_done(tasks: &mut [Task], number: usize) -> Result<(), String> {
    tasks[index_of(tasks, number)?].done = true;
    Ok(())
}

任务文件采用纯文本，每行一条记录，[x] 前缀表示完成。load 把“文件不存在”视为空列表，其他 IO 错误原样返回；index_of 把面向用户的 1 起始序号转换为内部索引，并统一检查越界。

入口：src/main.rs ​

rust
use std::path::PathBuf;

use clap::{Parser, Subcommand};
use todo::{add, load, mark_done, render, save};

#[derive(Parser)]
#[command(name = "todo", version, about = "一个最小的命令行待办工具")]
struct Cli {
    /// 任务文件路径
    #[arg(short, long, default_value = "todo.txt", global = true)]
    file: PathBuf,
    #[command(subcommand)]
    command: Command,
}

#[derive(Subcommand)]
enum Command {
    /// 添加一条任务
    Add { text: String },
    /// 列出全部任务
    List,
    /// 将任务标记为完成，序号从 1 开始
    Done { index: usize },
}

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let cli = Cli::parse();
    let mut tasks = load(&cli.file)?;
    match cli.command {
        Command::Add { text } => {
            let index = add(&mut tasks, &text);
            save(&cli.file, &tasks)?;
            println!("已添加 #{}: {text}", index + 1);
        }
        Command::List => {
            for (i, task) in tasks.iter().enumerate() { println!("{:>3}. {}", i + 1, render(task)); }
        }
        Command::Done { index } => {
            mark_done(&mut tasks, index)?;
            save(&cli.file, &tasks)?;
            println!("已完成 #{index}");
        }
    }
    Ok(())
}

#[derive(Parser)] 根据字段生成解析代码，文档注释会成为 --help 文本；#[command(subcommand)] 把枚举变体注册为子命令。global = true 让 --file 在子命令前后都能使用，Cli::parse() 在参数非法时打印帮助并以非零码退出。需要从标准输入读取时，可执行 let mut buffer = String::new(); std::io::stdin().read_to_string(&mut buffer)?;，并引入 std::io::Read；大文件改用 BufReader::lines()。所有 ? 最终由 main 的 Box<dyn std::error::Error> 统一处理，返回 Err 时进程以状态码 1 退出。

集成测试：tests/cli.rs ​

rust
use todo::{add, mark_done, render};

#[test]
fn add_then_complete() {
    let mut tasks = Vec::new();
    add(&mut tasks, "写测试");
    assert_eq!(render(&tasks[0]), "[ ] 写测试");
    mark_done(&mut tasks, 1).unwrap();
    assert_eq!(render(&tasks[0]), "[x] 写测试");
}

#[test]
fn rejects_zero_index() {
    assert!(mark_done(&mut Vec::new(), 0).is_err());
}

可运行示例：wc 风格的核心统计 ​

实现 wc 的核心统计逻辑Rust 2021
struct Stats { lines: usize, words: usize, chars: usize }

fn count(text: &str) -> Stats {
    Stats {
        lines: text.lines().count(),
        words: text.split_whitespace().count(),
        chars: text.chars().count(),
    }
}

fn main() {
    let text = "hello world\nsecond line\nthird";
    let stats = count(text);
    assert_eq!((stats.lines, stats.words, stats.chars), (3, 5, 29));
    println!("行: {}, 词: {}, 字符: {}", stats.lines, stats.words, stats.chars);
}

release 构建与分发 ​

cargo build --release 生成 target/release/todo；cargo install --path . 将其安装到 Cargo 的 bin 目录，供全局调用。发布前应确认版本号、--help 文本与退出码符合预期。

常见错误与工程建议 ​

  • 在 main 中 unwrap() 文件操作，遇到权限或路径错误时只打印 panic，脚本无法判断失败原因。
  • 混用 0 起始索引与 1 起始序号，导致 done 1 修改了第二条任务；在边界处统一转换。
  • 用 String 保存文件路径，遇到非 UTF-8 路径会失败；路径统一使用 PathBuf 与 Path。
  • 把业务逻辑写进 clap 的处理分支，测试必须启动进程；大文件一次性读入内存也会抬高峰值，按行处理时应使用 BufReader。

小结 ​

  • 采用 bin + lib 结构，让核心逻辑可测试，main 只处理参数与退出码。
  • clap 4 的派生宏把结构体与枚举映射为参数和子命令，文档注释即帮助文本。
  • 文件路径用 PathBuf，IO 错误向上传播；集成测试从外部调用公开 API，release 构建与 cargo install --path . 完成交付。
