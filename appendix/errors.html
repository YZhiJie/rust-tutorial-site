常见错误速查 ​

Rust 编译错误带有错误码、源码定位与修复建议。先读错误码与首行摘要，再看 ^ 标出的位置。需要完整解释时执行 rustc --explain E0382；日常用 cargo check 快速复查。

错误码含义常见触发点
E0382使用已被移动的值把 String、Vec 传给函数后继续使用
E0502可变借用与不可变借用冲突持有元素引用时修改集合
E0499同一值存在多个可变借用同时创建两个 &mut
E0597借用的值存活时间不够引用局部变量后向外返回
E0277trait 约束未满足对未实现 Display 的类型使用 {}
E0308类型不匹配字符串字面量赋给整数、分支返回类型不同
E0106缺少生命周期标注多个输入引用对应一个输出引用
E0433路径或模块无法解析未声明模块、crate 名写错

E0382：使用已被移动的值 ​

text
error[E0382]: borrow of moved value: `s`
 --> src/main.rs:5:20
5 |     println!("{s}");
  |               ^ value borrowed here after move
1
2
3
4

原因：String 拥有堆内存，赋值时发生移动（move），所有权转给新绑定，原变量失效；按值传参同样会移动。修复：需要两份数据时调用 .clone()；只读取时传 &s；后续不再使用原变量时接受移动并调整顺序。

rust
fn main() {
    let s = String::from("hello");
    let t = s;
    println!("{s}"); // 编译失败：borrow of moved value
}

E0502：可变借用与不可变借用冲突 ​

text
error[E0502]: cannot borrow `v` as mutable because it is also borrowed as immutable
 --> src/main.rs:4:5
4 |     v.push(4);
  |     ^^^^^^^^ mutable borrow occurs here
1
2
3
4

原因：first 持有指向 v 内部元素的不可变引用，且在 push 之后仍被使用；push 可能重新分配内存，使旧引用失效。修复：先复制需要的值（let first = v[0];）再修改；用作用域缩短引用寿命；需要修改不同片段时使用 split_at_mut。

rust
fn main() {
    let mut v = vec![1, 2, 3];
    let first = &v[0];
    v.push(4); // 编译失败
    println!("{first}");
}

E0499：同一值存在多个可变借用 ​

text
error[E0499]: cannot borrow `s` as mutable more than once at a time
 --> src/main.rs:4:14
4 |     let r2 = &mut s;
  |              ^^^^^^ second mutable borrow occurs here
1
2
3
4

原因：可变引用是独占借用（exclusive borrow），同时存在两个 &mut 会让编译器无法保证别名安全。修复：让两个可变借用的使用区间不重叠；通过函数参数把借用拆分到不同字段；确需运行时检查时使用 RefCell。

rust
fn main() {
    let mut s = String::from("a");
    let r1 = &mut s;
    let r2 = &mut s; // 编译失败
    r1.push('b');
    r2.push('c');
}

E0597：借用的值存活时间不够 ​

text
error[E0597]: `x` does not live long enough
 --> src/main.rs:5:13
5 |         r = &x;
  |             ^^ borrowed value does not live long enough
1
2
3
4

原因：x 在内部代码块结束时被释放，而 r 在代码块之外仍被使用；引用不能比被引用的值活得更久。修复：把声明移到与引用相同或更外层的作用域；返回拥有所有权的数据；让结构体持有值本身。

rust
fn main() {
    let r;
    {
        let x = 5;
        r = &x; // 编译失败：x 在代码块结束时释放
    }
    println!("{r}");
}

E0277：trait 约束未满足 ​

text
error[E0277]: `Point` doesn't implement `std::fmt::Display`
 --> src/main.rs:5:20
5 |     println!("{}", Point);
  |                    ^^^^^ `Point` cannot be formatted with the default formatter
1
2
3
4

原因：{} 要求类型实现 Display，而 Point 没有实现；泛型函数缺少 T: Trait 约束也会触发同一错误码。修复：实现 Display；调试输出改用 {:?} 并派生 Debug；泛型场景补上 where T: Display。

rust
struct Point;
fn main() {
    println!("{}", Point); // 编译失败：未实现 Display
}

E0308：类型不匹配 ​

text
error[E0308]: mismatched types
 --> src/main.rs:2:23
2 |     let count: i32 = "42";
  |                  ---   ^^^^ expected `i32`, found `&str`
1
2
3
4

原因：Rust 不会隐式转换类型，字符串字面量 &str 不能直接赋给 i32；match 各分支返回类型不一致也会报此错。修复：用 .parse::<i32>() 并处理错误；明确安全时用 as 转换数值；让各分支返回同一类型。

rust
fn main() {
    let count: i32 = "42"; // 编译失败
}

E0106：缺少生命周期标注 ​

text
error[E0106]: missing lifetime specifier
 --> src/main.rs:1:36
1 | fn longest(a: &str, b: &str) -> &str {
  |                  ----     ----     ^ expected named lifetime parameter
1
2
3
4

原因：返回值是引用，但有两个输入引用，编译器无法判断返回的引用来自哪个参数；省略规则只在输入引用唯一时自动套用。修复：显式声明 fn longest<'a>(a: &'a str, b: &'a str) -> &'a str；或返回拥有所有权的 String。

rust
fn longest(a: &str, b: &str) -> &str { // 编译失败
    if a.len() >= b.len() { a } else { b }
}

E0433：路径或模块无法解析 ​

text
error[E0433]: cannot find module or crate `utils` in this scope
 --> src/main.rs:2:5
2 |     utils::helper();
  |     ^^^^^ use of unresolved module or unlinked crate `utils`
1
2
3
4

原因：utils 既不是依赖 crate，也没有在当前模块声明；常见于漏写 mod utils;、文件路径与模块名不一致。修复：在 crate 根声明 mod utils;，并保证存在 src/utils.rs；跨模块调用写 crate::utils::helper()；检查依赖名。

rust
fn main() {
    utils::helper(); // 编译失败：模块未声明
}

排查顺序 ​

  1. 从第一条错误开始处理，后续错误常由前一条连锁产生；用 rustc --explain <错误码> 阅读完整说明；
  2. 按编译器标注的借用起止位置，缩短借用范围或调整所有权；
  3. 修复后重跑测试，避免只让代码“能编译”却改变语义。
