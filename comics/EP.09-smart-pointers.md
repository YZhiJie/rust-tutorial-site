# EP.09 智能指针家族

> 对应正文：[guide/09-smart-pointers.md](../docs/guide/09-smart-pointers.md)（Box：把值放到堆上 / Deref 与 Drop / Rc：共享所有权 / RefCell：内部可变性）

## 剧情回顾

- **第 1 格**：像素酱写递归枚举 `Cons(i32, List)`，编译器报 `error[E0072] recursive type has infinite size`——类型套自己，大小算不出。
- **第 2 格**：码叔揭秘：`Box<T>` 是固定大小的堆指针，递归类型因此有了确定大小；`Deref` 让它用起来像普通引用，`Drop` 离开作用域自动清理。
- **第 3 格**：齿轮君实证：`Rc<T>` 共享所有权（`Rc::clone` 只加计数不深拷贝），`RefCell<T>` 运行时借用检查，`Rc<RefCell<T>>` 组合出单线程共享可变。
- **第 4 格**：码叔结案——谁能拥有、谁能改、何时清，指针家族各司其职。

## 知识点拆解

### 第 1 格 · E0072 无限大小

- 递归类型直接或间接包含自身，不加包装就会无限展开；
- 编译期必须能确定每个类型的大小，因此编译器拒绝定义，报 `error[E0072]`；
- 解决思路：把"包含自身"换成"包含指向自身的指针"。

### 第 2 格 · Box 打断递归

```rust
enum List {
    Cons(i32, Box<List>),
    Nil,
}
```

- `Box<T>` 在堆上分配值，栈上只保留一个固定大小的指针，递归就此有了确定大小；
- `Deref` 让 `*b` 与方法调用自动穿透多层包装；`Drop` 在离开作用域时释放堆内存；
- `Box` 所有权唯一、无引用计数开销，也是大对象上堆与 `dyn Trait` 装箱的常用手段。

### 第 3 格 · Rc 与 RefCell

```rust
let counter = Rc::new(RefCell::new(0));
let a = Rc::clone(&counter);
*a.borrow_mut() += 1;
```

- `Rc<T>` 是引用计数指针，适用于单线程内多个所有者共享只读数据；`Rc::clone` 只增加计数，最后一个所有者销毁时才释放数据；
- `RefCell<T>` 把借用检查从编译期推迟到运行时：`borrow()` 不可变借用、`borrow_mut()` 可变借用，违反规则会 panic 而非编译失败；
- 两者组合得到单线程内可共享、可修改的状态；持有 `borrow_mut()` 期间应避免再次借用。

### 第 4 格 · 家族分工

- `Box` 独占堆值；`Rc` 单线程共享只读；`RefCell` 提供内部可变性；
- 跨线程场景换成 `Arc<T>`（原子引用计数）配合 `Mutex<T>`；
- 两个 `Rc` 相互指向会形成循环引用、计数永不归零，用 `Weak<T>` 弱引用打破。

## 坑点清单

1. `Rc<T>` 没有实现 `Send`，跨线程共享直接编译报错（cannot be sent between threads safely），要换 `Arc<T>`；
2. `RefCell` 同时持有两个 `borrow_mut()` 会在运行时 panic（already mutably borrowed），借用作用域应尽量短；
3. `Rc` 循环引用导致内存泄漏，用 `Weak<T>` 不增加计数的弱引用打破环。

## 自测 3 题（含答案）

1. 为什么递归类型需要 `Box`？——**递归类型直接包含自身会无限展开、大小无法确定；`Box` 是固定大小的堆指针，打断递归让大小在编译期可计算**。
2. `Rc::clone` 做了什么？——**只把强引用计数加一，不复制底层数据；最后一个所有者销毁、计数归零时才释放数据**。
3. `RefCell` 与编译期借用检查的区别？——**`RefCell` 把"共享不可变、独占可变"的检查推迟到运行时，违反规则时 panic，而不是编译失败**。
