# EP.04 所有权与借用检查

> 对应正文：[guide/04-ownership.md](../docs/guide/04-ownership.md)（所有权三条规则 / 引用与借用 / 悬垂引用 / 生命周期标注）

## 剧情回顾

- **第 1 格**：像素酱 `let s2 = s1;` 之后再 `println!("{s1}")`，收到 `error[E0382]: borrow of moved value`——String 赋值是移动。
- **第 2 格**：码叔拆解所有权三规则与 String 的栈/堆结构：move 让 s1 失效避免双重释放；`clone` 是显式深拷贝；`i32` 等 Copy 类型例外。
- **第 3 格**：齿轮君实证借用规则——任意多 `&T` 或唯一 `&mut T`；NLL 让 `first` 最后一次使用后 `data.push(4)` 合法，反例是 E0502。
- **第 4 格**：码叔结案三条坑点，并借悬垂引用 E0515 引出生命周期。

## 知识点拆解

### 第 1 格 · move 与 E0382

- 所有权三规则：每个值有且只有一个所有者；同一时刻只能有一个所有者；所有者离开作用域时，值被丢弃（drop），堆内存随之释放；
- `String` 是典型的"栈上元数据 + 堆上数据"：栈上记录 `ptr / len / capacity`，字节在堆上；
- `let s2 = s1;` 若逐字节复制元数据，就会有两个指针指向同一块堆内存，释放时双重释放（double free）；Rust 的选择是让 `s1` 失效——这就是 move；
- move 之后再使用原变量 → `error[E0382]: borrow of moved value: s1`。

### 第 2 格 · move、clone 与 Copy

```rust
let s2 = s1;          // move：所有权转移，s1 失效
let s3 = s2.clone();  // 显式深拷贝堆数据，两者各自独立
let b = a;            // i32 实现 Copy，按位复制，a 仍可用
```

- 非 `Copy` 类型在赋值、传参、返回时都会移动；
- `clone` 显式复制堆数据，可能代价较高，不应作为默认手段；
- `Copy` 类型：整数、浮点、`bool`、`char`、共享引用，以及全部由 `Copy` 类型组成的元组与数组；实现 `Copy` 的类型必须同时实现 `Clone`，复制是隐式且廉价的。

### 第 3 格 · 借用规则与 NLL

```rust
let mut data = vec![1, 2, 3];
let first = &data[0];
// data.push(4);      // error[E0502]：仍被不可变借用
println!("first = {first}");
data.push(4);        // NLL：first 最后一次使用后借用结束
```

- 核心规则：任意时刻，对同一个值要么存在任意多个 `&T`，要么存在唯一一个 `&mut T`，两者不能同时存在；
- `&` 与 `&mut` 冲突 → `error[E0502]`；同一作用域两个 `&mut` → `error[E0499]`；
- NLL（非词法生命周期，Rust 2018 起默认启用）：借用的有效范围到**最后一次使用**为止，而不是外层花括号结束；把 `push` 放在 `first` 最后一次使用之后就合法。

### 第 4 格 · 悬垂引用与生命周期

- 悬垂引用指向已释放的内存，Rust 在编译期拒绝：返回局部变量的引用 → `error[E0515]: cannot return reference to local variable`；
- 生命周期标注 `'a` 表示"引用至少存活多久"，它只描述引用之间的关系，**不能延长值的存活时间**；
- 函数从多个输入引用中返回一个引用时需显式标注，如 `fn longest<'a>(a: &'a str, b: &'a str) -> &'a str`；结构体持有引用同样需要标注。

## 坑点清单

> 🔗 正文对照：[《所有权、借用与生命周期 · 常见错误》](../docs/guide/04-ownership.md)

1. move 之后还用原变量 → `error[E0382]`；确实需要两份就显式 `clone`，并接受它的开销；
2. 可变借用与不可变借用同时存活 → `error[E0502]`（两个 `&mut` 同存则是 `E0499`）；修复思路是缩小借用范围或让修改顺序执行；
3. 试图返回悬垂引用 → `error[E0515]`；生命周期标注只能描述关系，救不回已经释放的值。

## 自测 3 题（含答案）

1. 为什么 `let s2 = s1;` 之后 `s1` 就不能用了？——**String 赋值是 move，所有权转给 s2；若两个指针都有效，释放时会双重释放，Rust 让 s1 失效来避免**。
2. 为什么 `let b = a;`（a 是 i32）之后 `a` 还能用？——**`i32` 实现了 `Copy`，赋值是按位复制而不是移动，复制隐式且廉价**。
3. NLL 解决了什么问题？——**非词法生命周期把借用的结束点从花括号提前到最后一次使用，让"先用完共享借用、再做可变修改"的代码合法（Rust 2018 起默认启用）**。
